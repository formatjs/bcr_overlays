# Perfetto overlay

Chromium 142 pin `d5bbee7afdf259af4212929ccbff467dd5349953`, after upstream v52.0.
Independent module: `perfetto@52.0.chromium142`.

Native targets `protozero_plugin`, `cppgen_plugin`, `ipc_plugin`, and their
`host_base`/`protozero` libraries use source lists imported from upstream's
native Bazel BUILD. Compiler plugins use BCR Protobuf 33.4, with Chromium's
bounds-abort and no-RTTI settings scoped to the compiler dependency.
Host tools retain upstream standalone Bazel build flags. `chromium_base` and
`chromium_protozero` use Chromium's captured build flags, generated by upstream's
Python script. Both runtime variants pass the generated wire test. Chromium
runtime consumers must compile without RTTI/exceptions. Browser embedding into
full base/Chrome remains pending.

`protos/**/*.proto` source labels expose exact pinned schemas for native
Chromium generation. No GN, Ninja, CMake, npm, or system compiler actions.
Upstream version-header script runs under hermetic rules_python.
Consumers select their toolchain; verification uses hermeticbuild LLVM 0.8.26.

The test runs all three plugins through real protoc, compiles generated
ProtoZero/object code, and checks serialization against fixed wire bytes.
Chromium's browser runtime now compiles real client, tracing service, IPC,
JSON export and minimal storage code. Full trace processor and remaining
upstream targets remain unported.

```sh
registry=$(mktemp -d)
python3 tools/stage_bcr_entry.py --source-registry overlays/perfetto/bcr --target-registry "$registry" --module perfetto --version 52.0.chromium142
cd overlays/perfetto/tests
bazel test --registry="file://$registry" --registry=https://bcr.bazel.build //:wire_test //:chromium_wire_test
```

Regenerate source inventory:

```sh
python3 overlays/perfetto/tools/import_host_tools.py /path/to/pinned/perfetto
python3 overlays/perfetto/tools/import_chromium_flags.py overlays/chromium/native/linux_x64.json.gz
buildifier -r overlays/perfetto
```

Registry metadata remains a local staging template; no BCR publication yet.

## Chromium browser runtime

`@perfetto//bazel:chromium_sdk.bzl` exposes `chromium_sdk`, compiling 159 original
C++ sources against a caller-owned protocol library and generated IPC/table/
descriptor files. No dependency on Chromium's module is introduced. Compiler
settings come from Chromium's exact browser graph, with toolchain paths and
modules delegated to Bazel. `DCHECK_ALWAYS_ON=1` propagates to callers; runtime
and headers must agree even when callers define `NDEBUG`.

BCR JsonCpp 1.9.6.bcr.2 and zlib 1.3.1.bcr.9 provide dependencies. A scoped
transition preserves Chromium's `JSON_USE_EXCEPTION=0` and `JSON_USE_NULLREF=0`
for library and headers. Canonical `perfetto/...` and Chromium's original
`third_party/perfetto/include/perfetto/...` paths are supported.

Chromium owns five native Python table/descriptor actions, three generated IPC
implementation files, and matching protocol output. Its runtime target is
`@chromium//third_party/perfetto:libperfetto`. The integration test records and
decodes a live in-process trace and checks dependency behavior.

Regenerate SDK source/compiler metadata from the pinned graph:

```sh
python3 overlays/perfetto/tools/import_chromium_sdk.py \
  overlays/chromium/native/linux_x64.json.gz /path/to/pinned/perfetto
buildifier -r overlays/perfetto
```

Platform metadata covers Linux AMD64/ARM64, macOS ARM64, and Windows
AMD64/ARM64. Windows selects its captured 142 SDK sources and disables IPC,
HTTPD, and the system consumer. Other platforms use 159 SDK sources. Host
generator binaries stay on Linux; target compiler settings follow target
platform. Perfetto foundation cross-builds pass all three non-Linux
targets; full Chromium browser integration remains in progress.

Regeneration accepts `--windows-amd64-graph`, `--windows-arm64-graph`, and
`--darwin-arm64-graph` alongside `--arm64-graph`. Regenerate runtime build flags
with `import_chromium_flags.py LINUX_GRAPH --windows-graph WINDOWS_GRAPH`.
